# Security policy

Do not post API keys, Telegram tokens, chat IDs, cookies, browser profiles, production databases, or sensitive logs in public GitHub issues or pull requests.

Before public vulnerability reporting is configured, use GitHub private vulnerability reporting when the repository enables it. Do not invent or publish a personal security email address.

If credentials are accidentally exposed, revoke or rotate them immediately and remove the affected local artifact from the working tree. Deleting a current file does not remove a credential from Git history.
